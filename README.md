# manga-crawler

Сервис отслеживания обновлений манги: краулер обходит сайты-источники,
Telegram-бот рассылает уведомления, админ-панель управляет источниками,
Telegram Mini App — основной пользовательский интерфейс (поиск, подписки).

Навигация по репозиторию и правила для AI-агентов — [AGENTS.md](AGENTS.md).
Планы работ: `miniapp/readme.md` (этапы мини-аппа), `backend/infrastructure.md`
(инфраструктура бэкенда).

### Почему мини-апп не может работать «локально»

Мини-апп открывается **на телефоне** в WebView Telegram: телефон скачивает
фронтенд и зовёт API прямо из браузера устройства.

1. Telegram web_app принимает **только HTTPS-адреса** — `localhost` и
   локальный HTTP не подходят в принципе.
2. Фронтенд можно раздать публично (GitHub Pages, бесплатно), но запросы
   `X-Telegram-Init-Data` уходят из браузера телефона в **miniapi** —
   значит, miniapi должен быть доступен из интернета по HTTPS.
   `localhost:8082` телефон не видит никак.
3. Быстрые туннели Cloudflare из домашней сети не поднимаются:
   `api.trycloudflare.com` отвечает за ~5,5 с (и через локальный прокси
   тоже), а внутренний таймаут `cloudflared` меньше — попытки исчерпаны,
   вариант закрыт.
4. Хостинг в РФ нежелателен: работа с Telegram из РФ опирается на VPN,
   стабильность `api.telegram.org` из РФ-сетей не гарантирована. Отсюда
   решение — зарубежный VPS с оплатой российскими картами.

Подробности выбора — в истории: постоянно-бесплатные варианты (Oracle,
GCP) не принимают регистрацию из РФ; PaaS (Render/Fly/Railway) не держат
фоновых демонов бота; RU-хостинг отпадает по п. 4.

## Переезд на VPS — чек-лист (точка продолжения)

### 0. Выбор сервера

- Рекомендация: **Timeweb Cloud, Амстердам, 2 vCPU / 2 ГБ / 20 ГБ NVMe**
  (~400–450 ₽/мес, почасовая оплата — легко снести стенд).
  Альтернативы с оплатой МИР/СБП: Aeza (~200–400 ₽), PQ.Hosting (~5 €),
  JustHost (от ~200 ₽). Только **KVM** (нужен Docker).
- Проекту хватает минимума: БД — 39 МБ, Go-процессы — десятки МБ RAM.
- Нужен домен (~200–300 ₽/год) или бесплатный поддомен DuckDNS — ради
  сертификата Let's Encrypt.

### 1. Probe краулера — первым делом, до переноса чего-либо

Запустить `cmd/probe` с нового сервера: если сайты-источники
(1.seimanga.me, a.zazaza.me, mgeko.cc) отвечают с датацентрового IP —
краулер переезжает вместе со всем; если нет — **краулер остаётся на
домашнем PC** и ходит в БД на VPS через SSH-туннель (PC выключен — просто
нет свежих глав, бот и мини-апп живут 24/7).

### 2. Перенос бэкенда

- docker-compose.yml переезжает почти как есть; добавить сервис
  **Caddy** (TLS автоматически) и сборку статик.
- БД: `pg_dump`/`restore`, объём копеечный.
- Схема same-origin — CORS исчезает:
  - `https://<домен>/` — статика мини-аппа (`miniapp/dist`);
  - `https://<домен>/mini-api/*` → miniapi:8082;
  - `https://admin.<домен>/` (или путь) — статика админки
    (`admin/dist`), `/admin-api/*` → adminapi:8081;
  - краулер/бот — не публикуются, только внутренние процессы.

### 3. Переменные окружения после переезда

| Переменная | Значение | Почему |
|---|---|---|
| `MINIAPP_URL` | `https://<домен>/` | Бот сам поставит Menu Button и web_app-кнопку в `/find` (этап 4); рестарт бота |
| `MINIAPI_ALLOWED_ORIGIN` | пусто | Same-origin — запросы не кросс-доменные |
| `VITE_API_BASE_URL` (сборка миниаппа) | не задавать | Пустое значение → запросы на относительный `/mini-api/...` того же origin |
| `DB_HOST` | `db` | Внутри compose |
| admin-переменные | как были | adminapi остаётся за Caddy; обязательно сильный пароль — теперь он за пределами localhost |

### 4. После переезда

- Проверить с телефона: приложение по `https://<домен>/`, поиск/подписки,
  deep link `t.me/<бот>?startapp=<id>` → карточка (закрывает приёмку
  этапов 4–5).
- Этап 6 (сдача): обновить корневой AGENTS.md и backend/README.md,
  прогнать ручной чек-лист (RU/EN, темы, iOS/Android/Desktop,
  истёкший initData).
- Этап 7 (сайт с Login Widget): плюс к этому — `/setdomain` в BotFather
  с новым доменом.

### План B — GitHub Pages (workflow готов)

Если VPS-сценарий затянется, мини-апп публикуется на Pages уже сейчас:
Settings → Pages → Source «GitHub Actions», переменная репозитория
`MINIAPI_PUBLIC_URL` (публичный HTTPS-адрес miniapi), merge в `master`.
Но при same-origin на VPS Pages не нужен — workflow оставить как резерв.
