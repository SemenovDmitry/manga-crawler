# Manga Crawler Backend

Telegram-бот для отслеживания выхода новых глав манги на сайтах readmanga и mintmanga.

Бот принимает ссылку на мангу, находит её RSS-ленту, сохраняет главы в PostgreSQL и
периодически (каждые 20 минут) проверяет обновления, рассылая уведомления подписчикам.

## Стек

- Go 1.24.5
- PostgreSQL (`github.com/lib/pq`)
- Миграции — `github.com/pressly/goose/v3`
- Конфигурация — `github.com/joho/godotenv`
- Telegram Bot API (напрямую через HTTP, без сторонних SDK)

## Запуск

```bash
# 1. Скопировать конфиг и заполнить TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID
cp .env.example .env

# 2. Запустить БД
docker-compose up -d manga-crawler-db

# 3. Запустить приложение
make server-start          # go run ./cmd/bot/main.go
```

Миграции применяются автоматически при старте. Подробности по Docker, БД и
пересборке — в [infrastructure.md](infrastructure.md).

## Структура

```
cmd/bot          — точка входа: инициализация, планировщик
db               — слой доступа к PostgreSQL, миграции
internal/parsers — парсеры источников и роутер
internal/telegram— клиент Telegram API, обработчики команд, шаблоны сообщений
internal/types   — общие модели: domain.go, telegram.go, xml.go
internal/utils   — утилиты: HTTP, RSS, разбор URL, gzip, диффы глав
```

## /cmd/bot

`main` — точка входа приложения: подключает БД, применяет миграции, запускает
Telegram-бота в режиме polling и планировщик проверки обновлений каждые 20 минут.

- `main` — запускает приложение.
    Принимает — ничего (использует переменные окружения).
    Возвращает — ничего (завершает процесс через `log.Fatalf` при ошибке миграций).

- `checkMangaUpdates` — проходит по всем активным источникам, получает список манги
  и запускает для каждого источника соответствующий парсер.
    Принимает `telegramBot *telegram.TelegramBot` — инициализированный бот для отправки уведомлений и сообщений об ошибках.
    Возвращает — ничего (ошибки логируются и не прерывают обработку остальных источников).

## /db

Слой доступа к PostgreSQL. Все функции используют единое ленивое подключение
(`GetDB`) и работают с моделями из `internal/types`.

### db.go

- `GetDB` — возвращает singleton-подключение к базе данных, создавая его при первом вызове.
    Принимает — ничего (читает `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` из окружения).
    Возвращает `*sql.DB` — пул соединений с PostgreSQL (при ошибке завершает процесс).

- `initDB` — инициализирует подключение к PostgreSQL и проверяет его пингом.
    Принимает — ничего (читает переменные окружения, подгружая `.env`).
    Возвращает `(*sql.DB, error)` — подключение; ошибку открытия или пинга.

- `CloseDB` — закрывает соединение с БД.
    Принимает — ничего.
    Возвращает `error` — ошибку закрытия соединения, либо `nil`, если соединения не было.

- `getEnv` — читает переменную окружения или возвращает значение по умолчанию.
    Принимает `key string` — имя переменной; `defaultValue string` — значение, если переменная пуста.
    Возвращает `string` — значение переменной или значение по умолчанию.

### migrations.go

- `RunMigrations` — применяет встроенные SQL-миграции через goose.
    Принимает — ничего (миграции встроены в бинарник через `embed`).
    Возвращает `error` — ошибку установки диалекта или применения миграций.

### chapter.go

- `GetChaptersByMangaID` — возвращает все главы манги, отсортированные по дате обнаружения (сначала новые).
    Принимает `mangaID int` — ID манги.
    Возвращает `([]types.Chapter, error)` — список глав; ошибку запроса или сканирования.

- `CreateChapter` — создаёт новую главу; при конфликте по паре (манга, URL) ничего не делает.
    Принимает `mangaID int` — ID манги; `url string` — URL главы; `title string` — название главы.
    Возвращает `(*types.Chapter, error)` — созданную главу, либо `nil`, если глава уже существовала; ошибку запроса.

- `CreateChapters` — создаёт несколько глав подряд и возвращает только реально новые.
    Принимает `mangaID int` — ID манги; `chapters []types.Chapter` — главы для сохранения.
    Возвращает `([]types.Chapter, error)` — список вновь добавленных глав; ошибку записи.

- `ChapterExists` — проверяет существование главы по манге и URL.
    Принимает `mangaID int` — ID манги; `url string` — URL главы.
    Возвращает `(bool, error)` — признак существования; ошибку запроса.

### manga.go

    Принимает `sourceID int` — ID источника.
    Возвращает `([]types.Manga, error)` — список манги; ошибку запроса или сканирования.

- `GetMangaByID` — возвращает мангу по ID.
    Принимает `id int` — ID манги.

- `GetMangaBySourceAndURL` — возвращает мангу по источнику и URL-части.
    Принимает `sourceID int` — ID источника; `url string` — URL-часть манги.
    Возвращает `(*types.Manga, error)` — мангу, либо `nil`, если не найдена; ошибку запроса.

- `UpdateMangaLastChapter` — обновляет информацию о последней главе и время проверки.
    Принимает `mangaID int` — ID манги; `chapterURL string` — URL главы; `chapterTitle string` — название главы.
    Возвращает `error` — ошибку обновления записи.

- `UpdateMangaLastCheck` — обновляет только время последней проверки манги.
    Принимает `mangaID int` — ID манги.

- `CreateManga` — создаёт новую мангу.
    Принимает `sourceID int` — ID источника; `url string` — URL-часть манги; `title string` — название.

- `GetMangaWithSubscribers` — возвращает мангу вместе со списком её подписчиков.
    Принимает `mangaID int` — ID манги.

- `GetMangaSubscribers` — возвращает активных подписчиков манги с включёнными уведомлениями.
    Принимает `mangaID int` — ID манги.
    Возвращает `([]types.TelegramUser, error)` — список подписчиков; ошибку запроса или сканирования.

### source.go

- `GetActiveSources` — возвращает все активные источники.
    Принимает — ничего.
    Возвращает `([]types.Source, error)` — список источников; ошибку запроса или сканирования.

- `GetSourceByName` — возвращает источник по имени парсера.

### subscription.go

- `CreateSubscription` — создаёт подписку пользователя на мангу; при повторной подписке включает уведомления.

- `GetSubscription` — возвращает подписку пользователя на мангу.

- `DeleteSubscription` — удаляет подписку пользователя на мангу.
    Принимает `userID int64` — Telegram ID пользователя; `mangaID int` — ID манги.
    Возвращает `error` — ошибку удаления.

- `GetUserSubscriptions` — возвращает все подписки пользователя с информацией об источнике,

    Принимает `userID int64` — Telegram ID пользователя.
    Возвращает `([]MangaWithSource, error)` — список манги с полями источника; ошибку запроса или сканирования.

### user.go

- `GetOrCreateUser` — находит пользователя Telegram по ID или создаёт его, обновляя имя и username.
    Принимает `id int64` — Telegram ID; `username string` — имя пользователя; `firstName string` — имя; `lastName string` — фамилия.

- `GetUserByID` — возвращает пользователя по Telegram ID.
    Принимает `id int64` — Telegram ID пользователя.
    Возвращает `(*types.TelegramUser, error)` — пользователя, либо `nil`, если не найден; ошибку запроса.

- `nullString` — преобразует строку в `sql.NullString`, считая пустую строку отсутствующим значением.

    Возвращает `sql.NullString` — значение с признаком `Valid = false` для пустой строки.

## /internal/parsers

Парсеры источников и роутер, выбирающий нужный парсер по имени источника.

### readmanga.go

- `ReadmangaParser` — проверяет обновления манги для источника: ищет RSS-ссылку на странице манги,
  получает фид, сохраняет новые главы, обновляет последнюю главу и рассылает уведомления подписчикам.
  Между мангами делает паузу 4 секунды, чтобы избежать бана.
    Принимает `telegramBot *telegram.TelegramBot` — бот для уведомлений; `source types.Source` — источник с базовым URL; `mangaList []types.Manga` — список манги для проверки.
    Возвращает `error` — всегда `nil`; ошибки по отдельным мангам логируются и не прерывают цикл.

### router.go

- `ParserFunc` — тип функции парсера, совместимый с `ReadmangaParser`.
    Принимает `telegramBot *telegram.TelegramBot` — бот; `source types.Source` — источник; `mangaList []types.Manga` — список манги.
    Возвращает `error` — результат обработки источника.

- `GetParser` — возвращает функцию парсера по имени источника.
    Принимает `sourceName types.SourceName` — имя парсера.
    Возвращает `(ParserFunc, error)` — функцию парсера; ошибку, если парсер не зарегистрирован.

- `RunParser` — запускает парсер, соответствующий источнику.
    Принимает `telegramBot *telegram.TelegramBot` — бот для уведомлений; `source types.Source` — источник; `mangaList []types.Manga` — список манги.
    Возвращает `error` — ошибку поиска парсера или ошибку его выполнения.

- `RegisterParser` — регистрирует новый парсер для имени источника.
    Принимает `sourceName types.SourceName` — имя парсера; `parser ParserFunc` — функция парсера.
    Возвращает — ничего.

## /internal/telegram

Клиент Telegram Bot API, обработчики команд пользователя и шаблоны сообщений.

### client.go

- `InitTelegramBot` — инициализирует бота из конфига и регистрирует меню команд.
    Принимает — ничего (читает `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` из `.env`).
    Возвращает `*TelegramBot` — настроенного бота (с `Enabled: false`, если токен не задан).

- `createTelegramBot` — создаёт структуру бота с HTTP-клиентом и URL API.
    Принимает `token string` — токен бота; `chatID string` — ID чата администратора.
    Возвращает `*TelegramBot` — готового бота, либо бота с `Enabled: false` при пустых параметрах.

- `SetBotCommands` — устанавливает меню команд бота в Telegram.
    Принимает `bot *TelegramBot` — бота.
    Возвращает `error` — ошибку маршалинга, запроса или ответа API.

- `StartPolling` — запускает бесконечный long polling обновлений и передаёт сообщения в `HandleMessage`.
    Принимает `bot *TelegramBot` — бота.
    Возвращает — ничего (работает до остановки приложения).

- `getUpdates` — получает обновления от Telegram API с указанного смещения.
    Принимает `bot *TelegramBot` — бота; `offset int64` — ID первого непрочитанного обновления.
    Возвращает `([]Update, error)` — список обновлений; ошибку запроса, чтения или парсинга.

### handlers.go

- `HandleMessage` — регистрирует пользователя и маршрутизирует входящее сообщение по командам
  (`/start`, `/help`, `/sources`, `/list`, `/add` или прямая ссылка на мангу).
    Принимает `bot *TelegramBot` — бота; `msg *TgMessage` — входящее сообщение.
    Возвращает — ничего (ответы отправляются в чат).

- `handleStart` — отправляет приветственное сообщение с описанием возможностей и команд.
    Принимает `bot *TelegramBot` — бота; `chatID int64` — ID чата.
    Возвращает — ничего.

- `handleHelp` — отправляет справку по командам.
    Принимает `bot *TelegramBot` — бота; `chatID int64` — ID чата.
    Возвращает — ничего.

- `handleSources` — отправляет список активных источников с их базовыми URL.
    Принимает `bot *TelegramBot` — бота; `chatID int64` — ID чата.
    Возвращает — ничего.

- `handleList` — отправляет список манги пользователя, сгруппированный по источникам.
    Принимает `bot *TelegramBot` — бота; `chatID int64` — ID чата; `userID int64` — Telegram ID пользователя.
    Возвращает — ничего.

- `handleAdd` — извлекает URL из текста команды `/add` и передаёт его в `handleAddManga`.
    Принимает `bot *TelegramBot` — бота; `chatID int64` — ID чата; `userID int64` — Telegram ID пользователя; `text string` — полный текст команды.
    Возвращает — ничего (при пустом URL просит прислать ссылку).

- `handleAddManga` — добавляет мангу по URL: ищет источник, проверяет существование манги,
  создаёт запись и главы, оформляет подписку и отвечает пользователю.
    Принимает `bot *TelegramBot` — бота; `chatID int64` — ID чата; `userID int64` — Telegram ID пользователя; `rawURL string` — ссылка на мангу.
    Возвращает — ничего (результат отправляется в чат).

- `sendMessageToChat` — отправляет сообщение в указанный чат.
    Принимает `bot *TelegramBot` — бота; `chatID int64` — ID чата; `text string` — текст в формате HTML.
    Возвращает `error` — ошибку отправки.

### messages.go

- `sendMessageToUser` — отправляет сообщение конкретному пользователю с отключённым превью.
    Принимает `bot *TelegramBot` — бота; `chatID int64` — ID чата получателя; `text string` — текст в формате HTML.

### types.go

- `TelegramBot` — конфигурация бота: токен, чат администратора, HTTP-клиент, базовый URL API и признак активности.
- `Message` — тело запроса `sendMessage`: ID чата, текст, режим разметки, флаг отключения превью.
- `APIResponse` — ответ Telegram API: признак успеха и описание ошибки.
- `Update` — обновление от Telegram: ID обновления и вложенное сообщение.
- `TgMessage` — входящее сообщение: ID, автор, чат, дата и текст.
- `TgUser` — автор сообщения: ID, признак бота, имя, фамилия, username.
- `TgChat` — чат: ID, тип, заголовок, username, имя и фамилия.
- `GetUpdatesResponse` — ответ на `getUpdates`: признак успеха и список обновлений.

## /internal/types

Общие модели данных проекта, разделённые по назначению на три файла:

```
domain.go    — доменные модели
telegram.go  — модели Telegram
xml.go       — структуры разбора RSS
```

Большинство структур имеют теги `db` (для выборки из PostgreSQL) и `json` (для сериализации).

### domain.go

Доменные модели приложения.

- `SourceName` — строковый тип-перечисление имени парсера; константы `SourceReadmanga` (`readmanga`) и `SourceMintmanga` (`mintmanga`).
- `AllSources` — срез всех поддерживаемых имён парсеров.
- `SourceName.IsValid` — проверяет, что имя является поддерживаемым парсером.
    Принимает — получатель `s SourceName` — проверяемое имя.
    Возвращает `bool` — `true` для `readmanga` или `mintmanga`.
- `Source` — источник (сайт для парсинга): ID, имя парсера, базовый URL, активность, даты.
- `Manga` — манга: ID, ID источника, URL, название, данные последней главы, время проверки, даты,
  а также не сохраняемые в БД поля `Chapters` и `Subscribers`.
- `UserSubscription` — подписка пользователя на мангу: ID, Telegram ID пользователя, ID манги, флаг уведомлений, дата подписки.
- `Chapter` — глава манги: ID, ID манги, URL, название, дата обнаружения.

### telegram.go

- `TelegramUser` — пользователь Telegram: ID (он же chat ID), username, имя, фамилия, активность, даты создания и обновления.

### xml.go

Структуры для разбора RSS-ленты источника.

- `RSS` — корневой элемент RSS-документа с вложенным каналом.
- `Channel` — канал RSS: заголовок, ссылка, список элементов.
- `Item` — элемент фида (глава манги): заголовок и ссылка.


## /internal/utils

Вспомогательные функции: HTTP-заголовки, разбор URL, работа с RSS, gzip и сравнение глав.

### DecompressGzip.go

- `DecompressGzipBody` — `DecompressGzipBody` декомпрессирует gzip данные
    Принимает `body []byte` — тело HTTP-ответа, возможно сжатое gzip.
    Возвращает `([]byte, error)` — распакованные данные; ошибку (в текущей реализации всегда `nil`, так как при неудаче возвращается исходное тело).

### ChaptersDiff.go

- `ChaptersDiff` — находит новые главы, сравнивая два списка сверху вниз по названию и URL.
    Принимает `a []types.Chapter` — актуальный список глав (обычно из RSS); `b []types.Chapter` — ранее известные главы.
    Возвращает `[]types.Chapter` — главы, которых не было в `b`; `nil`, если массив `a` пуст, все главы совпали или список `b` пуст.

### GetClientHeaders.go

- `GetClientHeaders` — формирует заголовки HTTP-запроса для загрузки HTML-страниц манги.
    Принимает `baseUrl string` — базовый URL сайта (подставляется в `Referer`).
    Возвращает `http.Header` — заголовки со случайным User-Agent, `Accept`, языком, кодировкой и `Connection: keep-alive`.

### GetRandomUserAgent.go

- `GetRandomUserAgent` — возвращает случайный User-Agent из набора популярных браузеров.
    Принимает — ничего.
    Возвращает `string` — случайную строку User-Agent.

### ParseMangaURL.go

- `ParsedMangaURL` — результат разбора ссылки на мангу: `BaseURL` (схема и хост), `Host` (хост без схемы), `MangaPath` (первый сегмент пути).
- `ParseMangaURL` — разбирает ссылку на мангу, извлекая базовый URL и путь.
    Принимает `rawURL string` — ссылка вида `https://a.zazaza.me/ugroza_v_moem_serdce__A5238`.
    Возвращает `(*ParsedMangaURL, error)` — разобранные части ссылки; ошибку при некорректном URL, неподдерживаемой схеме, отсутствии хоста или пути.

### rss.go

- `FindRSSLink` — находит ссылку на RSS-ленту манги на её странице: сначала регулярными выражениями
  по `<link>` и `<a>`, затем поиском в секции `<head>`; относительные ссылки приводит к абсолютным.
    Принимает `baseUrl string` — базовый URL источника; `mangaName string` — URL-часть манги.
    Возвращает `(string, error)` — абсолютный URL RSS-ленты; ошибку запроса, статуса ответа или отсутствия ссылки.

- `GetRSSFeed` — загружает и разбирает RSS-ленту в структуру канала, декомпрессируя gzip и удаляя BOM.
    Принимает `baseUrl string` — полный URL RSS-ленты.
    Возвращает `(types.Channel, error)` — канал с элементами фида; ошибку запроса, статуса, чтения или разбора XML.

- `TransformRSSFeed` — преобразует RSS-канал в модель манги, беря не более 10 последних глав.
    Принимает `feed types.Channel` — разобранный RSS-канал.
    Возвращает `(*types.Manga, error)` — мангу с заголовком, ссылкой и списком глав; ошибку (в текущей реализации всегда `nil`).

- `GetRSSHeaders` — формирует заголовки HTTP-запроса для загрузки RSS-ленты.
    Принимает `baseUrl string` — базовый URL RSS-ленты (подставляется в `Referer`).
    Возвращает `http.Header` — заголовки с `Accept: application/xml,text/xml,application/rss+xml` и случайным User-Agent.

## Схема базы данных

| Таблица | Назначение |
|---|---|
| `telegram_users` | Пользователи бота (ID Telegram используется как chat ID) |
| `sources` | Источники с именем парсера и базовым URL |
| `manga` | Отслеживаемая манга и данные её последней главы |
| `user_subscriptions` | Подписки пользователей на мангу с флагом уведомлений |
| `chapters` | Обнаруженные главы манги |

Миграция `db/migrations/001_init.sql` создаёт таблицы, индексы и наполняет `sources`
значениями `readmanga` (`https://a.zazaza.me`) и `mintmanga` (`https://1.seimanga.me`).
