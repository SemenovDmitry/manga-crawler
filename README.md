# manga-crawler-backend

Telegram-бот на Go для отслеживания обновлений манги: краулер обходит
сайты-источники, детектит новые главы и ставит уведомления в очередь,
бот их рассылает подписчикам.

## Архитектура

Три процесса, одна база Postgres: `cmd/bot` (Telegram-интерфейс и рассылка),
`cmd/crawler` (обход источников), `cmd/dbcheck` (утилита проверки БД).
Миграции зашиты в бинарник (goose) и применяются обоими процессами при
старте — порядок запуска контейнеров не важен.

### internal/crawler

Краулер: проходы по источникам, детект новых глав, постановка уведомлений.
Обязанности разнесены по узким сущностям: [fetcher.go](internal/crawler/fetcher.go) —
HTTP с ретраями и запретом кросс-доменных редиректов карточек,
[enumerate.go](internal/crawler/enumerate.go) — перечисление URL по sitemap
и каталогу, [processor.go](internal/crawler/processor.go) — обработка карточки,
[scheduler.go](internal/crawler/scheduler.go) — расписание полных обходов,
[notifier.go](internal/crawler/notifier.go) — очередь уведомлений,
[badpage.go](internal/crawler/badpage.go) — дампы непарсируемых страниц для
диагностики. Список источников перечитывается перед каждым проходом:
включение/выключение (`sources.enabled`), новые источники и смена движка
подхватываются без рестарта. Режимы: полный обход по персональному расписанию
каждого источника (`sources.next_full_crawl_at`, по умолчанию 2 недели) и
инкрементальный каждые `CRAWL_INTERVAL` (30 минут).

Перечисление карточек — по двум каналам. Sitemap — основной (1 запрос
вместо сотен), но у части сайтов он ограничен: a.zazaza.me кладёт в sitemap
не больше 10000 URL при каталоге ~29k манг (на странице `/list` — «Всего»).
Поэтому полный обход объединяет URL из sitemap и из пагинации каталога
(`/list?sortType=created&offset=…`, драйвер `CatalogLister`): карточка,
найденная через sitemap, через каталог повторно не парсится. Инкрементальный
проход дополнительно проверяет первые `CRAWL_CATALOG_PAGES` страниц каталога
(по умолчанию 2) — новые манги попадают в ограниченный sitemap не сразу.
Источники с полным sitemap (1.seimanga.me: 6295 URL против 6244 в каталоге)
от каталога приращения не получают. Драйвер mgeko каталог не поддерживает
и работает только по sitemap.

При возврате списка глав краулер сверяет с сохранённым состоянием
(`latest_chapter`, `chapters_count`) и кладёт уведомления подписчикам
в очередь `notifications`, которую разбирает бот. Уведомления ищутся
только у уже известных манг — первичная загрузка каталога проходит
без спама по чатам.

### internal/crawler/parsers

Контракты и драйверы сайтов: общие типы (карточка, глава, статусы) —
в корне пакета, драйверы движков — в подпакетах
[grouple](internal/crawler/parsers/grouple) (seimanga, zazaza)
и [mgeko](internal/crawler/parsers/mgeko). Новый сайт на известном движке
не требует кода — достаточно INSERT в `sources` с именем движка; новый
движок добавляется реализацией `SourceDriver` и case в [registry.go](internal/crawler/registry.go).
Из карточки извлекается статус публикации `publication_status`
(`ongoing`/`completed`/`hiatus`/`cancelled`/`discontinued`) — манги
в финальных статусах не перепарсиваются в 30-минутных проходах, даже если
подписка остаётся. Удалённые манги (HTTP 200 с «противоречит правилам сайта»)
пропускаются без ошибок.

### internal/storage

Доступ к Postgres: источники и их расписание полных обходов, манги,
подписки, очередь уведомлений; миграции — goose, SQL-файлы в
[internal/storage/migrations](internal/storage/migrations), применяются
обоими процессами под advisory-блокировкой. Ключевые сущности: `Source`
(персональное расписание обхода, флаг `enabled`), `Manga` (url-часть
уникальна в паре с источником, статус публикации, время проверки),
`Notification` (очередь с отметкой отправки).

### internal/telegram

Telegram-бот: long polling, обработка команд (`/start`, `/find`, `/list`,
`/help`), inline-клавиатуры и рассылка уведомлений из очереди
(`StartNotificationDispatch` в отдельной горутине). Форматирование
сообщений и тексты — здесь же; пакет не знает про краулер, только
про общую базу.

### internal/env, internal/types

`env` — чтение переменных окружения с дефолтами и мягкой обработкой
некорректных значений (предупреждение в лог, значение по умолчанию).
`types` — общие структуры домена (XML-типы sitemap и пр.).

## Команды бота

- `/start` — регистрация пользователя чата в базе и приветствие
- `/find` — поиск манги по названию
- `/list` — мои подписки
- `/help` — справка

## Разведка сайтов (cmd/probe)

`go run ./cmd/probe` — скачивает robots.txt, sitemap (и под-карты) и примеры страниц
(манга, каталог `/list`, поиск `/search?q=`) для 1.seimanga.me и a.zazaza.me
в каталог `probe-output/`. Запускается на машине пользователя: сайты блокируют
датацентровые IP. Результаты используются для реализации парсера.

## Оценка объёма первичного обхода

~6.3k манг (1.seimanga.me) и ~29k (a.zazaza.me — каталог целиком; через
лимитированный sitemap доступно лишь ~10k); при задержке
`CRAWL_REQUEST_DELAY=1s` полный проход занимает несколько часов, далее
только 30-минутные инкрементальные проходы.

## Запуск

1. Скопируйте `.env.example` в `.env`, впишите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
2. `go run ./cmd/bot` — или `docker compose up -d --build`.

Подробности: [infrastructure.md](infrastructure.md).
