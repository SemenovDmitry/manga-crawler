# manga-crawler-backend

Telegram-бот на Go для отслеживания обновлений манги.

## Команды бота

- `/start` — регистрация пользователя чата в базе и приветствие
- `/help` — справка

## Разведка сайтов (cmd/probe)

`go run ./cmd/probe` — скачивает robots.txt, sitemap (и под-карты) и примеры страниц
(манга, каталог `/list`, поиск `/search?q=`) для 1.seimanga.me и a.zazaza.me
в каталог `probe-output/`. Запускается на машине пользователя: сайты блокируют
датацентровые IP. Результаты используются для реализации парсера.

## Краулер (cmd/crawler)

Отдельный процесс. Режимы обхода:
- **Полный обход** каталога через sitemap — по расписанию каждого источника
  в БД: `sources.next_full_crawl_at`, персональный интервал
  `sources.full_crawl_interval_secs` (по умолчанию 1209600 сек = 2 недели).
  Новый источник (INSERT в `sources`) обходится полностью при первом старте,
  дальше — по собственному расписанию; у источников оно разное.
- **Инкрементальный проход** каждые `CRAWL_INTERVAL` (30 минут): новые URL
  из sitemap + перепроверка подписанных манг со статусом `ongoing`.
  Если у источника наступило время полного обхода — вместо инкрементального
  выполняется полный.

Перечисление карточек — по двум каналам. Sitemap — основной (1 запрос
вместо сотен), но у части сайтов он ограничен: a.zazaza.me кладёт в sitemap
не больше 10000 URL при каталоге ~29k манг (на странице `/list` — «Всего»).
Поэтому полный обход объединяет URL из sitemap и из пагинации каталога
(`/list?sortType=created&offset=…`, драйвер `CatalogLister`): карточка,
найденная через sitemap, через каталог повторно не парсится. Инкрементальный
проход дополнительно проверяет первые `CRAWL_CATALOG_PAGES` страниц каталога
(по умолчанию 2) — новые манги попадают в ограниченный sitemap не сразу.
Источники с полным sitemap (1.seimanga.me: 6295 URL против 6244 в каталоге)
от каталога приращения не получают. Драйвер mgeko каталог не поддерживает
и работает только по sitemap.

Парсеры карточек живут в [internal/crawler/parsers](internal/crawler/parsers):
общие типы и контракт драйвера — в корне пакета, драйверы движков —
в подпакетах [grouple](internal/crawler/parsers/grouple) (seimanga, zazaza)
и [mgeko](internal/crawler/parsers/mgeko). Из карточки извлекается статус публикации
`publication_status` (`ongoing`/`completed`/`hiatus`/`cancelled`/`discontinued`)
по тегам «Перевод Завершён»/«Перевод Приостановлен» на странице. Манги
в финальных статусах не перепарсиваются в 30-минутных проходах, даже если
подписка остаётся (проверить их можно только полным обходом). Удалённые
манги (HTTP 200 с «противоречит правилам сайта») пропускаются без ошибок.

При возврате списка глав краулер сверяет с сохранённым состоянием
(`latest_chapter`, `chapters_count`) и кладёт уведомления подписчикам
в очередь `notifications`, которую разбирает бот.

Оценка объёма первичного обхода: ~6.3k манг (1.seimanga.me) и ~29k
(a.zazaza.me — каталог целиком; через лимитированный sitemap доступно лишь
~10k); при задержке `CRAWL_REQUEST_DELAY=1s` полный проход занимает
несколько часов, далее только 30-минутные инкрементальные проходы.

Запуск: `go run ./cmd/crawler` (или сервис `manga-crawler-crawler` в docker-compose).

## Запуск

1. Скопируйте `.env.example` в `.env`, впишите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
2. `go run ./cmd/bot` — или `docker compose up -d --build`.

Подробности: [infrastructure.md](infrastructure.md).
