# Правила для AI-агентов (manga-crawler admin)

Применяйте при работе в каталоге `admin/`. Дополняют общие правила репозитория;
при расхождении приоритет у явного указания человека.

## Компоненты

### Нейминг

**Общий принцип:** компоненты с версткой (React-компоненты, JSX) — **PascalCase**;
всё остальное (хуки, сторы, утилиты, обычные модули) — **camelCase** (без дефисов).
В названиях папок дефисы тоже не используются.

- **Файлы компонентов с версткой** (`.tsx` с JSX) — PascalCase, имя файла =
  имени компонента: `Sources.tsx`, `RecrawlButton.tsx`,
  `ConfirmDialog.tsx`, `LocaleSwitch.tsx`.
- **UI-примитивы** в `src/components/ui/` — так же: `Button.tsx`, `Card.tsx`,
  `Table.tsx`, главный экспорт совпадает с именем файла.
- **Файлы без верстки** — camelCase без дефисов: `queries.ts`, `format.ts`,
  `toastStore.ts`, `errorMessages.ts` (только логика, типы, сторы —
  без JSX).
- **Папки с компонентами (фичи) — PascalCase**: `Sources`, `ChatUsers`,
  `MangaList`. `features` — служебная папка-группировка, с маленькой буквы.
- **Структура папки фичи**: корневой файл с тем же именем, что и папка
  (`Sources/Sources.tsx`, компонент без суффиксов), рядом `index.ts` с
  default-импортом (`export { Sources as default } from "./Sources"`),
  плюс сопутствующие модули без верстки (`queries.ts`).
  Импорт снаружи — только через папку: `import Sources from "@/features/Sources"`.
- **Папки** — без дефисов: PascalCase для папок с компонентами (`Sources`,
  `ChatUsers`), camelCase для остальных (`ui`, `hooks`) или одно слово
  (`manga`, `lib`).
- **`src/routes/` не трогаем**: TanStack Router использует собственные
  правила нейминга файл-роутинга (`_auth.tsx`, `chat-users.tsx`,
  `$id.tsx`, `__root.tsx`), которые несовместимы с этой схемой. Имена
  файлов и папок маршрутов остаются как требует генератор routeTree —
  переименовывать их под общие правила запрещено.
- **Хуки** — файл camelCase, имя хука с `use`: `useApiToast.ts` →
  `useApiToast`. Хуки данных фичи живут в `queries.ts` этой фичи
  (`features/sources/queries.ts`), не поодиночке в `hooks/`.
- **Типы из API** — без префиксов и суффиксов, повторяют домен:
  `Source`, `ChatUser`, `Manga`. Не `ISource`, не `SourceType`.
- **Константы модулей** — SCREAMING_SNAKE: `sourcesKey`, `chatUsersKey`.
- **Событийные колбэк-пропсы** — `on` + прошедшее время:
  `onSetEnabled`, `onLogout`, `onOpenChange`.

### Выбор компонентов

- Нативный элемент + Tailwind в shadcn-манере — дефолт (см. `switch` на
  чекбоксе, `dialog` на `<dialog>`). Сторонние UI-библиотеки запрещены без
  явного решения человека.
- Ничего не копируем из интернета без адаптации под тему: только
  семантические классы (`bg-background`, `text-muted-foreground`), никаких
  сырых цветов (`text-blue-500`) — иначе рвётся связь с CSS-переменными темы.

### Разделение слоёв: components vs lib

- `src/components/` — только файлы с версткой (`.tsx` с JSX). Логика,
  от которой зависит компонент, живёт рядом по слою, а не по фиче:
  стор состояния — в `src/lib/` (пример: `toastStore.ts` — состояние тостов,
  `Toaster.tsx` — их разметка), утилиты и форматирование — тоже `lib/`.
- Признак для решения: если файл не возвращает JSX — он не в `components/`.
- Логика конкретной фичи (запросы, мутации) — в `features/<фича>/`,
  не в `lib/`.

## Слой API (`src/api`)

- Типы и пути запросов — только из `schema.gen.ts` (генерируется
  `npm run gen:api` из `backend/docs/openapi.yaml`). Ручные интерфейсы,
  дублирующие схему, запрещены.
- Ответы через `unwrap()`; ошибки — `ApiError` со статусом. Прямой `fetch`
  вне `client.ts`/`refresh.ts` не используется.
- 401 обрабатывается middleware автоматически (refresh-очередь); код страниц
  не пишет свою логику refresh.

## Состояние и данные

- Серверное состояние — только TanStack Query: ключи запросов — массивы с
  доменным именем (`["sources"]`, `["chat-users"]`).
- Мутации, меняющие строку таблицы — optimistic updates с откатом в
  `onError` и инвалидацией в `onSettled`.
- Клиентское состояние (тосты, локаль) — минимальные сторы без внешних
  библиотек, пока не потребуется больше.

## i18n

- Весь видимый текст — через `t()`; RU-словарь базовый, EN обязателен к
  синхронизации. Новые ключи добавляются в оба файла одним изменением.
- Сообщения об ошибках бэкенда не хардкодятся: известные статусы маппятся в
  [errorMessages.ts](src/api/errorMessages.ts), неизвестные показываются
  как есть.

## Маршруты

- Файл-роутинг TanStack Router: страница = тонкий файл в `src/routes/`,
  компонент живёт в `features/`. Гард — только в `_auth.tsx`.
- Ссылки между маршрутами — типизированный `Link`/`navigate`, не `<a href>`.

## Проверки перед сдачей

- `npx tsc --noEmit`, `npx @biomejs/biome check .`, `npx vite build` —
  все три зелёные; новые ключи i18n добавлены в RU и EN.
