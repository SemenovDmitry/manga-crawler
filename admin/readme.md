# Админ-панель manga-crawler

Веб-интерфейс над `cmd/adminapi` (Go/gin, `:8081`, префикс `/admin-api`).
Контракт API — [backend/docs/openapi.yaml](../backend/docs/openapi.yaml):
auth (login / refresh-ротация / logout), sources, chat-users, manga (CRUD + поиск).

## Стек

| Слой           | Выбор                                                 | Почему                                                                                                                                                   |
| -------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Сборка         | Vite + React 19 + TypeScript (strict)                 | быстрый dev, современный стандарт                                                                                                                        |
| UI             | shadcn/ui + Tailwind CSS                              | компоненты в репозитории, полный контроль, минимальный бандл                                                                                             |
| Таблицы        | TanStack Table (headless)                             | сортировка/пагинация под себя, стили shadcn                                                                                                              |
| Данные         | TanStack Query                                        | кеш, рефетч, состояние загрузки/ошибок                                                                                                                   |
| API-клиент     | генерация из `docs/openapi.yaml` (openapi-typescript) | единый источник правды с бэкендом, типобезопасность                                                                                                      |
| i18n           | react-i18next, типизированные ключи                   | RU (базовый) + EN, JSON-словари                                                                                                                          |
| Валидация форм | react-hook-form + zod                                 | схемы переиспользуются для create/update                                                                                                                 |
| Роутинг        | TanStack Router                                       | типизированные маршруты, search-параметры с zod-валидацией (фильтры таблицы манги живут в URL), `beforeLoad`-гарды, нативная интеграция с TanStack Query |
| Линт/формат    | Biome                                                 | один инструмент вместо ESLint + Prettier, быстро, минимум конфига                                                                                        |

## Аутентификация (токены в cookie)

Оба токена живут в HttpOnly-cookie (`SameSite=Strict`, `Path=/admin-api`,
`Secure` в проде) — фронтенд их не читает и никуда не подкладывает, браузер
отдаёт их сам; кража через XSS и CSRF закрыты по построению. Правки на
бэкенде (этап 0): `Set-Cookie` в `login`/`refresh`/`logout`, чтение токенов из
cookie вместо `Authorization: Bearer` и JSON-тела, cookieAuth в спеке,
обновление тестовых хелперов защищённых ручек. `admin_sessions` не меняется —
миграций нет.

## Архитектура фронтенда

- **Auth**: токены только в HttpOnly-cookie; при 401 автоматический
  `POST /auth/refresh` с очередью параллельных запросов; logout чистит cookie
  на бэкенде; guard маршрутов по ответу `me`-подобной проверки либо по
  факту успешного запроса (без доступа к токенам из JS).
- **Dev-прокси**: Vite проксирует `/admin-api → http://localhost:8081`
  (CORS на бэкенде нет и не нужен; cookie ходят в одном домене через прокси).
- **Структура**: `src/api` (сгенерированный клиент + обёртки с auth),
  `src/features/{auth,sources,chat-users,manga}`, `src/components/ui` (shadcn),
  `src/i18n/{ru,en}.json`.

## Этапы

Каждый этап привязан к операциям API по `operationId` из
[backend/docs/openapi.yaml](../backend/docs/openapi.yaml) — схемы запросов и
ответов не дублируются здесь, они приходят из генерации клиента.

0. **Правки бэкенда** (делаются до фронтенда этапов 2–4):
   - **Cookie-аутентификация**: оба токена переносятся в HttpOnly-cookie
     (`SameSite=Strict`, `Path=/admin-api`, `Secure` в проде).
     `login`/`refresh`/`logout` ставят `Set-Cookie` вместо (и вместе с)
     JSON-ответа; `refresh`/`logout` читают refresh из cookie, а не из тела;
     `requireAuth` переключается с `Authorization: Bearer` на access-cookie;
     в спеке bearerAuth → cookieAuth. Тесты: обновить хелперы защищённых
     ручек в `server_test.go`. `admin_sessions` не меняется — миграций нет.
   - `createManga`: ловить нарушение уникальности `(parse_source_id, url)`
     (pq 23505) → `409 Conflict` вместо 500; обновить спеку; `docs/schema.sql`
     не требуется (схема не меняется).
   - `listManga`: добавить `total` в ответ `MangaList` (SQL `COUNT(*)` с тем же
     фильтром) — для классического пагинатора «страница X из Y»; обновить спеку.
   - Прогнать `go test ./internal/adminapi/...` и `go generate` для oapi.
1. **Каркас**: Vite-проект в `admin/`, Tailwind + shadcn, генератор клиента из
   OpenAPI-спеки (`pnpm gen:api`), dev-прокси, TanStack Router (дерево
   маршрутов + гарды), i18n-инициализация, Biome (линт + формат), `base: './'`.
   Базовая тема: тёмная тёплая, коричневая («coffee») — за основу берётся
   стандартная тёмная палитра shadcn с осветлёнными фонами (не чёрная, а
   тёмно-коричневая с повышенной светлотой, нейтральные акценты заменяются на
   тёплые). Токены размещаются в `@layer base` файла `globals.css`
   (каскадные слои Tailwind), тёмная тема — дефолт (`html.dark` без
   переключателя на каркасе). Компоненты используют только
   семантические классы (`bg-background`, `text-muted-foreground`).
   Если появится макет в Figma — его цвета/радиусы переносятся руками в те же
   переменные (разовая операция, токен-пайплайн не нужен).
   _(без ручек — только инфраструктура)_
2. **Аутентификация**: страница логина, refresh-механика, защищённые маршруты,
   выход. Токены только в HttpOnly-cookie — JS их не видит; при 401 —
   автоматический `refresh` с очередью параллельных запросов. Ошибки бэкенда
   (русские строки `{error}`) маппятся на локализованные тосты по коду
   статуса, неизвестные — как есть.
   - `login` — форма входа, сервер ставит cookie
   - `refresh` — автоматическое обновление при 401 (очередь параллельных запросов)
   - `logout` — выход, сервер отзывает сессию и гасит cookie
3. **Источники и пользователи чатов**: таблица источников (движок, URL,
   статус, время последнего полного обхода; переключатель enabled, кнопка
   «пересоздать полный обход» с подтверждением); таблица chat-users
   (блокировка/разблокировка). Переключатели — optimistic updates с откатом.
   - `listSources` — таблица источников, фильтр `enabled`
   - `setSourceEnabled` — переключатель в строке таблицы
   - `resetSourceFullCrawl` — кнопка «пересоздать полный обход»
   - `listChatUsers` — таблица пользователей
   - `setChatUserEnabled` — блокировка/разблокировка
4. **Каталог манги**: таблица с поиском по названию, фильтрами по источнику и
   статусу публикации, пагинацией «страница X из Y» по `total`; карточка,
   создание, редактирование (частичный PATCH), удаление с подтверждением.
   Дубликат при создании → локализованный тост по 409.
   - `listManga` — таблица; search-параметры URL → `query`, `source_id`,
     `status`, `limit`, `offset`
   - `getManga` — карточка манги
   - `createManga` — форма создания (409 → «такая манга уже есть»)
   - `updateManga` — форма редактирования (частичный PATCH)
   - `deleteManga` — удаление с подтверждением
5. **Полировка**: empty/error-состояния, README по запуску (тёмная тема —
   дефолт с этапа 1, здесь только подстройка оттенков по готовым страницам).
   Vitest: refresh-интерсептор и zod-схемы форм.
   Сборка и деплой (go:embed либо nginx) — отдельным этапом позже.
   _(без новых ручек — доработка по всем страницам)_

Покрытие спеки на этапе 4: 13 из 13 операций задействованы
(+ этап 0 расширяет ответы `MangaList.total` и `createManga` → 409).

Маршруты: `/login`, `/` → редирект на `/manga`, `/sources`, `/chat-users`,
`/manga`, `/manga/new`, `/manga/$id`, `*` → 404.

## Запуск (dev)

```bash
cd admin
npm install      # см. примечание про pnpm ниже
npm run gen:api  # типы клиента из ../backend/docs/openapi.yaml
npm run dev      # Vite на :5173, прокси /admin-api → :8081
```

Бэкенд: `go run ./cmd/adminapi` из `backend/` (нужны `JWT_SECRET`,
`ADMIN_PASSWORD_HASH` — см. `backend/.env.example`).

### Пакетный менеджер

Основной менеджер — **npm** (`package-lock.json`). pnpm в этой среде не
используем: его структура node_modules строится на символических ссылках,
которые здесь требуют прав администратора (см. `.npmrc` — при появлении прав
можно вернуться на pnpm, удалив `.npmrc` и `package-lock.json`).

### Ограничения песочницы (для AI-агентов)

- `child_process.spawn` из Node блокируется (vite/esbuild его используют) —
  команды `npm run build`/`npm run dev` выполнять с полным доступом.
- Сборке нужен доступ к системному Temp; при отказе перенаправить:
  `TEMP=...admin/.tmp-build`.

## Статус

- **Этап 0 (бэкенд)** — готов: cookie-auth, 409 на дубликат, `total` в списке
  манги; тесты зелёные.
- **Этап 1 (каркас)** — готов: Vite + React 19 + Tailwind v4 (coffee-тёмная
  тема в `@layer base`), shadcn-компоненты (button/card/input/badge),
  генератор клиента `gen:api`, TanStack Router (гард `_auth`, редиректы,
  404), i18n RU/EN, Biome, `base: './'`; `npm run build` зелёный.
- **Этап 2 (аутентификация)** — готов: refresh-очередь при 401 (один refresh
  на всплеск параллельных запросов, ровно один повтор), событие
  `unauthorized` → тост + редирект на логин, тосты без внешних зависимостей
  (store + Toaster), маппинг ошибок бэкенда на локализованные по коду
  статуса (401/403/404/409/5xx), logout/login чистят кеш Query и очередь
  refresh.
- **Этап 3 (источники и chat-users)** — готов: таблица источников (движок,
  URL, время последнего полного обхода; switch enabled, кнопка recrawl с
  confirm-диалогом), таблица пользователей чатов (switch блокировки);
  мутации с optimistic updates и откатом при ошибке; новые ui-компоненты
  (table/switch/dialog/spinner), форматирование дат по локали.
- **Этап 4 (каталог манги)** — готов: таблица (title + alt_titles, источник,
  последняя глава, главы, статус-badge, время последней проверки) с поиском
  по названию (дебаунс 300 мс) и фильтрами по источнику и статусу — всё в
  URL через `validateSearch` (zod); пагинация «стр. X из Y» по `total`;
  карточка с режимами view/edit, создание, редактирование (частичный PATCH —
  пустые опциональные поля уходят как `undefined`), удаление с
  подтверждением; 409 на дубликат — локализованный тост. Формы —
  react-hook-form + zod (v4), пустой статус публикации = omit.
- Этап 5 — полировка: впереди (Vitest на refresh-очередь и zod-схемы форм,
  empty/error-состояния; тёмная тема — дефолт с этапа 1, здесь только
  подстройка оттенков).
